# Контрольні запитання
1) HTTP — це “stateless” протокол (без стану). Що це означає для розробника і чому сервер не впізнає одного й того ж користувача на різних сторінках без додаткових інструментів?

Кожен HTTP-запит є незалежним. Він не пам'ятає попередні запити. Якщо на page1.php ми задамо певну змінну і дамо їй значення, то на page2.php змінна буде порожньою (Undefined). Для розробника це означає, що «пам'ять» між сторінками треба організовувати самому. Тому сервер без додаткових інструментів не може зрозуміти, що запити надійшли від одного й того ж користувача.

2) Яка різниця між Cookie та Сесією ($_SESSION)? Де фізично зберігаються дані змінних сесії (на клієнті в браузері чи на сервері)?

Cookie зберігаються в браузері (на клієнті), їх можна переглянути й підмінити, тому класти туди важливі дані небезпечно. Дані $_SESSION фізично лежать на сервері. Клієнту відправляється лише ідентифікатор сесії.

3) Що таке PHPSESSID і яку функцію виконує цей файл cookie?

Це назва cookie, у якій браузер записує ID сесії. З кожним запитом браузер автоматично відправляє цю cookie серверу, а PHP за цим ID знаходить потрібний файл або запис із даними сесії. Саме вона з'єднує запити від одного користувача.

4) Для чого необхідно викликати session_start() на самому-самому початку файлу, навіть до тегу <html> чи пробілів? Яку помилку ви отримаєте, якщо викличете це після HTML-коду (Headers already sent)?

Cookie це HTTP-заголовок, а заголовки не можна відправити, коли тіло відповіді вже почало виводитись. Тому session_start() має йти до будь-якого echo, <html> чи пробілу. Якщо викликати її після виводу, буде помилка Headers already sent. Також її потрібно викликати на кожній сторінці, де є сесія, інакше $_SESSION буде порожнім.

5) Що виконує функція header('Location: ...') і чому після перенаправлення обов’язково треба писати exit (або die)?

Функція надсилає браузеру заголовок перенаправлення, і той переходить на іншу сторінку. Але PHP-скрипт не зупиняється, і код нижче все одно виконається. Тому одразу після перенаправлення потрібен exit (або die), щоб закриті дані чи дії не відпрацювали для неавторизованого користувача.
